## HybAs Aware repository structure guide

This document explains the **intended public repository layout** for HybAs Aware and how that layout maps to workflow execution, isolate organization, generated outputs, configuration files, and runtime artifacts.

It is meant to give users a clean mental model of the project before they run anything.

This guide reflects the repository model you chose:

* `bactomics/` is the top-level project workspace
* isolates are direct children of `bactomics/`
* `bactomics/hybas/` contains the workflow package
* `bactomics/hybas/validation/` contains the downstream computational analysis workflow
* the folder name `validation` is simply the current folder name and should not be treated as a problem

For installation, see `INSTALL.md`. For usage patterns, see `USAGE.md`. For config fields, see `CONFIGURATION.md`.

---

## 1. Top-level layout

The intended public layout is:

```text
bactomics/
├── <isolate_1>/
├── <isolate_2>/
├── <isolate_3>/
└── hybas/
```

### Meaning of the top-level layout

* `bactomics/` is the overall working area
* each isolate is a direct child directory of `bactomics/`
* `hybas/` is the packaged workflow directory
* isolate data and workflow code are intentionally separated

This separation is useful because the workflow code can remain stable while isolate directories are added, updated, or removed over time.

---

## 2. What lives under `bactomics/`

At the top level, there are two main classes of content.

### A. Isolate directories

These hold sample-specific inputs, intermediate files, final outputs, metadata, logs, and downstream analysis results.

Examples:

```text
bactomics/
├── isolate_A01/
├── isolate_B02/
└── isolate_C03/
```

### B. The HybAs workflow package

This contains the Snakemake workflows, configuration files, the Streamlit control app, CI profile, controller environment definition, and the downstream workflow code.

Example:

```text
bactomics/
└── hybas/
```

---

## 3. Workflow package layout under `hybas/`

The intended package structure is:

```text
bactomics/hybas/
├── Hybas.smk
├── config.yaml
├── samples.tsv
├── environment.yaml
├── .condarc
├── app/
│   └── hybas_streamlit_app.py
├── ci/
│   ├── config.ci.yaml
│   └── samples.ci.tsv
└── validation/
    ├── HybAs_validation.smk
    ├── validation_config.yaml
    ├── scripts/
    ├── envs/
    └── config/
```

### What each top-level item in `hybas/` does

#### `Hybas.smk`

The canonical main Snakemake workflow for HybAs.

This is the primary assembly and analysis DAG.

#### `config.yaml`

Main workflow configuration.

Controls:

* base directory
* sample sheet path
* threads
* polishing behavior
* module toggles
* taxon-aware logic
* database locations

#### `samples.tsv`

Main isolate sample sheet.

Defines the isolate set and optional isolate-level overrides.

#### `environment.yaml`

Controller environment definition.

This is the bootstrap environment used to launch:

* Snakemake
* Streamlit
* controller-side dependencies

It is **not** the full dependency specification for every rule tool.

#### `.condarc`

Repository-specific Conda configuration used during Snakemake execution.

This should be part of the documented execution model for CLI runs.

#### `app/`

Contains the Streamlit control interface.

#### `ci/`

Contains the reduced CI profile.

#### `validation/`

Contains the second Snakemake DAG, documented publicly as the **Downstream Computational Genome Analysis Workflow**.

## 4. Isolate directory layout

Each isolate is expected to be a direct child of `bactomics/`.

Example:

```text
bactomics/
└── isolate_A01/
```

Within each isolate, HybAs expects a standard layout.

### Typical isolate structure

```text
bactomics/
└── isolate_A01/
    ├── raw/
    │   ├── illumina/
    │   └── nanopore/
    ├── work/
    ├── reports/
    ├── annotation/
    ├── logs/
    ├── metadata/
    ├── benchmarks/
    └── validation/
```

### Directory roles

#### `raw/`

Input data for the isolate.

This is the main user-supplied input area.

#### `work/`

Intermediate and final workflow outputs from the main HybAs workflow.

#### `reports/`

QC and summary reports generated by the main workflow.

#### `annotation/`

Annotation outputs such as GFF and FAA files.

#### `logs/`

Per-isolate run logs and related diagnostics.

#### `metadata/`

Structured run metadata, provenance, checksums, summaries, and tool-version outputs.

#### `benchmarks/`

Snakemake benchmark outputs where applicable.

#### `validation/`

Outputs from the Downstream Computational Genome Analysis Workflow.

This is an output area under the isolate, separate from the workflow code directory `bactomics/hybas/validation/`.

## 5. Input directories inside each isolate

The main workflow resolves reads from:

```text
raw/illumina/
raw/nanopore/
```

### `raw/illumina/`

Expected to contain paired-end Illumina reads.

Patterns recognized by the workflow include R1/R2-aware filenames such as:

* `*_R1*.fastq.gz`
* `*_R2*.fastq.gz`
* and equivalent `.fq` / uncompressed variants

### `raw/nanopore/`

Expected to contain ONT reads.

Patterns recognized by the workflow include:

* `*.fastq.gz`
* `*.fq.gz`
* `*.fastq`
* `*.fq`

### Example input layout

```text
bactomics/
└── isolate_A01/
    └── raw/
        ├── illumina/
        │   ├── isolate_A01_R1.fastq.gz
        │   └── isolate_A01_R2.fastq.gz
        └── nanopore/
            └── isolate_A01_ont.fastq.gz
```

## 7. Downstream analysis output layout inside each isolate

The second workflow writes into the isolate-local:

```text
validation/
```

This is different from the workflow code folder at:

```text
bactomics/hybas/validation/
```

That distinction is important.

* `bactomics/hybas/validation/` contains the workflow code and config
* `bactomics/<isolate>/validation/` contains the generated downstream results

### Typical downstream output structure

```text
bactomics/
└── isolate_A01/
    └── validation/
        ├── phase1/
        ├── phase2/
        ├── phase3/
        ├── plots/
        ├── multiqc/
        ├── multiqc_custom/
        ├── report/
        ├── metadata/
        ├── logs/
        └── benchmarks/
```

### Phase directories

#### `validation/phase1/`

Contains stage progression and stage-summary outputs.

Representative contents include:

* stage manifest tables
* BUSCO-by-stage tables
* dnadiff stage comparison tables
* Phase 1 metadata

#### `validation/phase2/`

Contains stage-level gene-space and BUSCO hotspot/degradation outputs.

Representative contents include:

* gene-space summary tables
* BUSCO hotspot tables
* BUSCO degradation event tables
* Phase 2 metadata

#### `validation/phase3/`

Contains edit-density, hotspot, clustering, classification, and final summary outputs.

Representative contents include:

* edit summary tables
* window-density tables
* hotspot ranking tables
* spatial clustering tables
* classification tables
* final summary tables and JSON
* Phase 3 metadata

### Plotting and reporting directories

#### `validation/plots/`

Contains phase-specific figures and dashboard-style outputs.

#### `validation/multiqc/`

Contains downstream MultiQC outputs where enabled.

#### `validation/report/`

Contains downstream bundled reporting artifacts.

#### `validation/metadata/`

Contains downstream provenance and summary metadata.

#### `validation/logs/`

Contains downstream run logs.

#### `validation/benchmarks/`

Contains downstream benchmark outputs.

## 8. The difference between workflow code and generated outputs

One of the easiest mistakes users make is confusing workflow code directories with isolate output directories.

### Workflow code lives under:

```text
bactomics/hybas/
```

This includes:

* Snakefiles
* YAML configs
* CI profile
* Streamlit app
* downstream workflow scripts
* environment definitions

### Generated outputs live under:

```text
bactomics/<isolate>/
```

This includes:

* read inputs
* intermediate files
* final assemblies
* QC reports
* annotation outputs
* metadata
* downstream analysis outputs

If this distinction is kept clear, many path and troubleshooting problems disappear.

## 10. Streamlit app placement and role

The Streamlit control app is placed under:

```text
bactomics/hybas/app/
```

Current file:

```text
app/hybas_streamlit_app.py
```

### Why it belongs there

It is part of the workflow package, not part of any isolate output tree.

It acts as a control layer for:

* launching the main workflow
* launching the downstream workflow
* editing the sample sheet
* editing key config values
* monitoring runtime logs

It should not be treated as a replacement for the underlying repository structure.

---

## 11. CI directory placement and role

The CI profile lives under:

```text
bactomics/hybas/ci/
```

This directory contains the reduced execution profile used for lighter-weight runs or workflow testing.

It is separate from:

* the standard configuration files
* the downstream workflow code
* the isolate outputs

This keeps the CI profile from being confused with the main analytical path.

---

## 12. Global provenance and project-level artifacts

The main workflow may also write project-level provenance outside the isolate-local metadata directories, under a top-level provenance area inside `base_dir`.

This means not every artifact is guaranteed to live only inside a single isolate folder.

Users should therefore think of repository structure in two layers:

* isolate-local outputs
* project-level provenance or runtime artifacts

If your final release standardizes this further, that can be reflected later in both the README and this document.

## 13. Naming rules that affect structure

### Isolate directory names

For reliable workflow behavior, isolate folder names should:

* be unique
* use only letters, numbers, underscores, and hyphens
* avoid spaces
* avoid shell-special characters
* exactly match the `isolate` value in `samples.tsv`

### Canonical main Snakefile name

Use:

```text
Hybas.smk
```

as the canonical main workflow name in public documentation.

### Downstream workflow name in documentation

The directory name remains:

```text
validation/
```

But the public-facing workflow name should be:

**Downstream Computational Genome Analysis Workflow**

## 14. Runtime mental model

A useful way to think about the structure is:

### Code and control live here

```text
bactomics/hybas/
```

### Biological inputs and outputs live here

```text
bactomics/<isolate>/
```

### The second analysis workflow is coded here

```text
bactomics/hybas/validation/
```

### The second analysis workflow writes results here

```text
bactomics/<isolate>/validation/
```

This distinction is one of the most important concepts in the repository.

---

## 15. Common structure mistakes to avoid

### Confusing `bactomics/hybas/validation/` with `bactomics/<isolate>/validation/`

One is workflow code.
The other is generated output.

### Placing isolates under `bactomics/hybas/`

For this repository version, isolates should remain direct children of `bactomics/`, not nested inside the workflow package.

### Treating `environment.yaml` as a rule environment file

It belongs to the controller layer under `bactomics/hybas/`.

### Putting config files inside isolate directories

The main workflow config, CI config, and downstream workflow config belong under the workflow package, not inside per-isolate directories.

### Renaming isolate folders without updating the sample sheet

The isolate folder name must remain aligned with `samples.tsv`.
