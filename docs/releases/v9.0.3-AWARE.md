# HybAs AWARE 9.0.3 — Alpha integrity patch

This is the near-beta v9 maintenance line, published as a prerelease. It applies
the relevant pre-beta audit fixes while retaining the existing Illumina-only,
ONT-only and hybrid routes, Unicycler assembly, regular AWARE behavior and
polishing options. No HybAs 10 platform manifests, PacBio routes or AWARE+ modes
are introduced. Existing default selections and scientific thresholds remain.

## Evidence integrity changes

- Each scheduled Medaka run executes in a fresh retained attempt directory;
  earlier native BAM/HDF intermediates cannot be reused silently. New output is
  published at `work/polishing/medaka/current/consensus.fasta`, leaving a legacy
  `work/polishing/medaka/consensus.fasta` intact. Downstream promotion checks the
  execution receipt against the published consensus hash. Normal unchanged
  scheduler reruns remain no-ops.
- Model resolution uses the pinned Medaka command and records the actual model
  file, content hash and read metadata coverage. Automatic selection requires one
  known basecaller identity on every input read and cannot fall back to a native
  default. If metadata is missing, incomplete or mixed, inspect the original
  basecalling information and configure `medaka_model` explicitly. This is a
  deliberate correction to the former silent fallback, not a new model choice.
  An explicit model choice is not presented as metadata-verified suitability.
- v9 already preserves original FASTQ headers during merging. The v10-specific
  read namespacing adapter is not included in this backport.
- The aggregate QC label becomes `processing_evidence_status`; analytical
  suitability is separately `NOT_ASSESSED`. Recorded BUSCO completeness of 0%
  cannot be interpreted as an analytical pass. No universal biological acceptance
  threshold is introduced. HTML explains legacy recording-check PASS labels.
- Confidence compares competitors at the selected taxonomic rank, so an own
  genus is not a rival to its species. Selection and per-platform cleaning are
  unchanged, including v9's existing conservative absent-platform handling.
- BUSCO lineage content hashes are scheduler dependencies, checked before and
  after execution. The actual dataset digest appears in the summary and resource
  receipt. Changing contents invalidates results even when filenames, sizes,
  timestamps and `.complete` remain unchanged.

## Operational and validation boundaries

Retained Medaka attempts consume disk space; remove them only through an explicit
maintenance decision after preserving needed evidence. Consensus and receipt
are individually atomically replaced, and their pairing is verified downstream.
Configured model files are content-tracked. Named/default model stores are
resolved and hashed when scheduled, not continually monitored during no-op runs.
BUSCO datasets must remain immutable during analysis.

Regression tests use harmless synthetic fixtures and tool-contract stubs to
verify orchestration, reruns, identities and presentation. They do not validate
Medaka neural inference, genome accuracy or biological safety. Real pinned-tool
qualification, representative independent datasets and clean-install testing
remain required before any beta promotion. The checked-release workflow publishes
`hybas-v9.0.3-AWARE` only after the Python matrix and report-browser checks pass.
